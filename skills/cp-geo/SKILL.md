# cp-geo · Видимость в ответах нейросетей

GEO — молодая тема с огромным объёмом контента и крошечным объёмом фактуры. Скилл держит границу: подтверждённого ровно четыре блока, всё остальное — принципы без первоисточника.

Главное, что скилл сообщает пользователю первым: **GEO не заменяет SEO и не идёт параллельно ему. Он надстроен сверху.** Всё остальное — следствие.

## Когда не этот скилл

- Нужна обычная выдача: семантика, кластеры, техаудит, Clean-param, позиции и CTR → `cp-seo`. Здесь — только ответы нейросетей.
- Нужно физически поправить сайт, залить robots.txt, посмотреть логи сервера → `cp-web`.
- Нужно написать сам материал, который будут цитировать → `cp-content-plan`, дальше профильный текстовый скилл.
- Нужен сценарий регулярного сбора данных о видимости → `cp-automation`.

## Врезка констант

### Подтверждено ровно четыре вещи

**1. Яндекс: раздел «Видимость сайта в ответах Алисы AI» (уровень A).** Появился 07.04.2026. Единственный официальный GEO-инструмент из существующих.

| Параметр | Значение |
|---|---|
| Где | Вебмастер → Эффективность → «Видимость сайта в Алисе AI» |
| Метрика | **«Доля упоминаний»** (Share of Voice) — процент участия сайта в источниках, на которые Алиса опирается при формировании ответа. Официальное название у Яндекса — именно «доля упоминаний»; английский термин ходит по отраслевым материалам, но самим Яндексом не используется — в клиентских отчётах писать русское название |
| Диапазоны частоты | топ-3 / топ-10 / топ-20 |
| Глубина данных | последние **3 месяца** |
| Обновление | **раз в неделю** |
| Выгрузка | список запросов доступен |
| Влияние на ранжирование | нет, инструмент аналитический |

> **Ключевое ограничение, из которого следует вся стратегия: данные основаны на запросах, по которым сайт показывается в поисковой выдаче.** Нет сайта в выдаче по запросу — нет и статистики по нему. GEO у Яндекса надстроен над классическим SEO.

**2. Официальная рекомендация Яндекса — принцип ЭПОС (уровень A).**

| Буква | Что означает |
|---|---|
| **Э** — экспертность | глубина раскрытия темы |
| **П** — полезность | решение задачи пользователя |
| **О** — оригинальность | отличие от конкурентов |
| **С** — содержательность | полнота и структурированность |

Это всё, что Яндекс говорит о содержании. Расшифровки вида «сколько абзацев» и «где ставить вывод» — уже не Яндекс.

**3. Google: отдельной оптимизации под AI Overviews не существует (уровень A).** Прямые формулировки документации: нет дополнительных требований для появления в AI Overviews или AI Mode и никаких специальных оптимизаций; не нужно создавать новые машиночитаемые файлы, AI-текстовые файлы или разметку; все существующие основы SEO продолжают работать.

Требуется только, чтобы страница была проиндексирована, соответствовала техтребованиям и могла показываться со сниппетом. Управление — обычными директивами: `nosnippet`, `data-nosnippet`, `max-snippet`, `noindex`. Ограничение использования в других системах — `Google-Extended`.

Следствие, о котором надо предупредить: **закрыть показ в AI Overviews отдельно нельзя** — директивы сниппета режут и обычный сниппет в выдаче. Перед применением сверять формулировки в справке на дату.

**4. Краулеры OpenAI — разные боты с разным назначением (уровень A).**

| Бот | Назначение | Что будет при запрете |
|---|---|---|
| `GPTBot` | обучение моделей | контент не используется при подготовке систем |
| `OAI-SearchBot` | **отображение сайта в результатах поиска ChatGPT** | сайт не появляется в поиске ChatGPT |
| `OAI-AdsBot` | проверка страниц, поданных как объявления | — |
| `ChatGPT-User` | действие, инициированное пользователем в ChatGPT | правила robots.txt могут не применяться: инициатор — человек |

Изменения robots.txt обрабатываются примерно **24 часа**.

> **Самая частая и самая дорогая ошибка: закрыть `GPTBot` и вместе с ним потерять `OAI-SearchBot`.** Это два разных бота. Первый про обучение, второй про трафик. Решения по ним принимаются отдельно.

### Всё остальное

Русскоязычные материалы по GEO — общие принципы без фактуры: ни выборок, ни методологии, ни ссылок на документацию. Уровень C. Применять можно, выдавать за факт — нет.

## Вход

Одним блоком.

1. Домен и тематика: по каким вопросам сайт вообще должен всплывать в ответах.
2. Подключён ли Яндекс.Вебмастер, есть ли доступ к разделу «Видимость в Алисе AI».
3. Как сайт стоит в **обычной** выдаче Яндекса по этим темам. Если никак — начинаем с `cp-seo`.
4. Есть ли доступ к логам сервера (без них ИИ-краулеров не увидеть).
5. Текущий robots.txt: что в нём про ИИ-ботов сейчас.
6. Позиция по обучению моделей: отдавать контент на обучение или нет — это решение владельца, не техническая настройка.
7. Есть ли уникальные данные, которых нет у других: свои замеры, своя статистика, свой опыт с числами.

## Процесс

### 1. Проверь фундамент, прежде чем делать GEO

Сайт не в индексе, не ранжируется или закрыт от сниппетов — GEO обсуждать рано. Отправляй в `cp-seo`, возвращайся, когда появятся позиции. Это не формальность: у Яндекса данные по видимости в Алисе основаны на запросах, по которым сайт показывается в поисковой выдаче, — нет показов, нет и статистики.

### 2. Сними базу по Алисе AI

Вебмастер → Эффективность → «Видимость сайта в Алисе AI». Зафиксируй: «доля упоминаний» (Share of Voice), распределение по диапазонам топ-3 / топ-10 / топ-20, выгрузи список запросов.

Помни про механику: данные за 3 месяца, обновление раз в неделю. **Значит, реакция на изменения измеряется неделями, а не днями.** Обещать «через два дня посмотрим эффект» нельзя.

### 3. Настрой robots.txt под ИИ-краулеров

Блок ниже. Решение по каждому боту принимается осознанно и записывается: почему открыт, почему закрыт.

### 4. Приведи контент к ЭПОС и к формату, из которого удобно цитировать

Официальная часть — ЭПОС. Практическая — блок «Цитируемость» ниже, целиком уровень C.

### 5. Поставь наблюдение

Логи сервера на ИИ-ботов плюс регулярная фиксация упоминаний бренда. Блок «Аудит» ниже. Автоматизация регулярной выгрузки → `cp-automation`.

### 6. Сравнивай с собой

Порог — собственная динамика «доли упоминаний» и собственный список запросов. Чужих бенчмарков по GEO не существует: инструмент новый, публичных сравнительных данных нет.

## robots.txt для ИИ-краулеров · шаблон с разбором

**Сначала правило, из-за которого ломается половина файлов:** робот выполняет **только одну группу** — самую подходящую под своё имя. Директивы из `User-agent: *` он **не наследует**. Если завёл отдельную секцию для бота, повтори в ней все нужные запреты.

```
# 1. Общее правило для всех роботов, у кого нет своей секции
User-agent: *
Disallow: /admin/
Disallow: /cart/
Disallow: /search/

# 2. Яндекс: те же запреты плюс склейка параметров
User-agent: YandexBot
Disallow: /admin/
Disallow: /cart/
Disallow: /search/
Clean-param: utm_medium&utm_campaign

# 3. OpenAI, обучение моделей — решение владельца
User-agent: GPTBot
Disallow: /

# 4. OpenAI, показ в поиске ChatGPT — оставить открытым
User-agent: OAI-SearchBot
Disallow:

# 5. OpenAI, проверка страниц из объявлений
User-agent: OAI-AdsBot
Disallow:

# 6. Perplexity
User-agent: PerplexityBot
Disallow:

# 7. Anthropic
User-agent: ClaudeBot
Disallow:

# 8. Использование контента в других системах Google
User-agent: Google-Extended
Disallow: /

Sitemap: https://example.ru/sitemap.xml
```

**Построчно.**

| Строка | Что делает | Что учесть |
|---|---|---|
| `User-agent: *` | базовое правило для всех, у кого нет своей секции | не наследуется теми, у кого секция есть |
| `User-agent: YandexBot` | секция основного поискового робота Яндекса | сюда идёт `Clean-param` — директива есть только у Яндекса, разбор в `cp-seo` |
| `GPTBot: Disallow: /` | контент не используется при подготовке моделей | **на показ в поиске ChatGPT не влияет** — это другой бот |
| `OAI-SearchBot: Disallow:` | пустая директива = разрешено всё | закроешь — сайт исчезнет из поиска ChatGPT. Обычно закрывать не нужно |
| `OAI-AdsBot` | проверка страниц, поданных как объявления | закрывать имеет смысл, только если рекламы там нет и не будет |
| `PerplexityBot` | краулер Perplexity | назначение и имена ботов сверять по документации сервиса на дату |
| `ClaudeBot` | краулер Anthropic | то же |
| `Google-Extended: Disallow: /` | ограничивает использование контента в других системах Google | **не управляет показом в AI Overviews** — тот регулируется директивами сниппета |
| `Sitemap:` | межсекционная директива | одна на файл, полный URL |

**Чего в шаблоне нет намеренно.** `ChatGPT-User` — действие инициирует человек, правила robots.txt к нему могут не применяться, запрет ненадёжен. И `llms.txt` — по документации Google новые машиночитаемые файлы не требуются; общей поддержки со стороны поисковых систем не подтверждено. Хочешь — добавляй, но как эксперимент, а не как обязательный элемент.

**После правки:** изменения обрабатываются примерно 24 часа. Проверь файл анализатором robots.txt в Вебмастере на конкретных URL и убедись, что не задел поисковых роботов.

## Цитируемость · практика (уровень C целиком)

Ниже — рабочие гипотезы. Первоисточника, подтверждающего, что это влияет на попадание в ответы нейросетей, нет. Проверяются наблюдением за «долей упоминаний» и упоминаниями. Официальная часть — только ЭПОС выше.

**1. Отвечай на вопрос сразу.** Прямой ответ в первых предложениях раздела, дальше — обоснование и детали. Подводка на три абзаца перед ответом мешает и человеку, и машине.

**2. Один блок — один вопрос.** Подзаголовок формулируется как вопрос или как утверждение-ответ, а не как «Введение» и «Немного истории».

**3. Факты с датами и источниками.** «По данным <источник>, на <дата> — <значение>». Фраза без атрибуции в цитату не годится: её нечем подтвердить.

**4. Уникальные данные, которых нет у других.** Свой замер, своя выборка, свой разбор случая с числами. Пересказ общеизвестного не даёт причины цитировать именно тебя. Это же — единственный настоящий вклад в «О» из ЭПОС.

**5. Сущности названы однозначно.** Полное имя бренда, компании, продукта, автора — без местоимений и сокращений в ключевых местах. Одна и та же сущность называется одинаково по всему сайту и во внешних упоминаниях.

**6. Структура, которую легко разобрать.** Списки, таблицы, определения. Разметка Schema.org — общий знаменатель обеих поисковых систем, ставить стоит по любому раскладу.

**7. Стабильные адреса.** Материал, который цитируют, не переезжает и не переписывается до неузнаваемости. Смена URL обнуляет накопленное.

Чего **не** делать: набивать страницу «вопросами и ответами» ради формата, публиковать сгенерированные обзоры без собственных данных, переписывать чужие материалы. Это ровно противоположно «О» и «Э» в ЭПОС.

## Аудит · как увидеть, что происходит

### ИИ-краулеры в логах сервера

Единственный способ узнать, ходят ли боты и куда. Доступ к логам — через хостинг или подрядчика (`cp-web`).

Что искать: строки User-agent с `GPTBot`, `OAI-SearchBot`, `OAI-AdsBot`, `ChatGPT-User`, `PerplexityBot`, `ClaudeBot`, `Google-Extended`, `YandexBot`.

Что считать по каждому боту: сколько обращений за период, какие URL, какие коды ответа. Что читать из результата:

| Картина | Вывод |
|---|---|
| Бота нет вовсе | либо закрыт в robots.txt, либо сайт ему неинтересен, либо не нашёл |
| Ходит, но получает 4xx/5xx | техническая проблема, чинить в первую очередь |
| Ходит только по одному разделу | остальное недоступно или не связано перелинковкой |
| Резко вырос трафик бота | нагрузка на сервер — вопрос к хостингу, не к контенту |

**User-agent подделывается.** Для чистоты проверяй принадлежность IP способом, описанным в документации соответствующего сервиса.

### Упоминания бренда в ответах

**Официально измеримо только у Яндекса** — «доля упоминаний» в Вебмастере.

Для остальных систем публичного инструмента нет. Ручной метод, уровень C:

1. Составь фиксированный список из 20–40 запросов, по которым бренд **должен** всплывать. Список не меняется между замерами, иначе сравнивать нечего.
2. Прогоняй его с одинаковой периодичностью (например, раз в месяц) в тех системах, которые важны.
3. Фиксируй по каждому запросу: упомянут бренд или нет, есть ли ссылка, что именно сказано, нет ли искажения фактов.
4. Сравнивай только с собственными прошлыми замерами.

Оговорка, без которой замер бессмысленен: **ответы нейросетей недетерминированы** — один и тот же запрос даёт разные ответы, плюс влияют регион, история диалога и версия модели. Один замер не значит ничего; смысл появляется в серии. На выборке в несколько запросов разница неразличима — правило малых чисел действует и здесь.

## Чек-лист перед выдачей

- Сказано прямо: GEO надстроен над SEO, без позиций в обычной выдаче он не работает.
- `GPTBot` и `OAI-SearchBot` разведены, по каждому записано отдельное решение с причиной.
- В robots.txt секции ботов не наследуют `*` — нужные запреты продублированы.
- Отмечено, что `Google-Extended` не управляет показом в AI Overviews.
